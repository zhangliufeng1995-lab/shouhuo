## 3. 已实现的业务模块与流程

### 3.1 主循环（Day Cycle）

```
[开始一天]
    └→ 生成冒险者 (shop_adventurer.gd)
         → 玩家选择：收购 / 讨价 / 拒绝
         → 收购/讨价成交 → 物品进入库存、生态减1、生成下一位冒险者
         → 拒绝 → 直接生成下一位冒险者

[结束一天 (_on_btn_end_day)]
    1. 顾客购买 (shop_customer.gd)
       - 柜台等级影响顾客数: 1 + int(lv * 0.5) + rand(3)
       - 顾客随机偏好的材料类型
       - 从货架筛选 → 价格合理性判定 buy_chance
       - 成交 → gold增加、货架移除、销售记录、信誉更新
       - 生态稀缺（population<30%容量）→ 顾客溢价10~40%

    2. 怪物袭击 (shop_monster.gd)
       - 触发概率: 15% + day * 0.1%（随时间略增）
       - 弹窗选项：请守卫(30+day*2金) / 硬扛(成功率70%-day*1%,最低30%)
       - 胜→可能掉落材料(精英60%/普通30%)
       - 败→随机丢失一件货架商品

    3. 生态模拟 (EcosystemSim.gd)
       - 调用 simulate_day()
       - 更新 season, day

    4. UI刷新
       - 刷新库存/货架显示
       - 更新生态面板（如果已打开）
       - 生成下一位冒险者（为明天准备）
```

### 3.3 冒险者生成流程 (`shop_adventurer.gd`)

```
generate_adventurer(shop):
    1. 随机名字 （ADV_FIRST_NAMES + "·" + ADV_LAST_NAMES）
    2. 随机性格: ["急躁","普通","耐心","狡猾","豪爽"]
    3. 30%概率跨域（从非荧光苔原域取货，外地货溢价1.2~1.8倍）
       - 跨域特殊名字池: CROSS_DOMAIN_NAMES
    4. 从目标域按种群加权选择物种
    5. 计算货物价值:
       基础值 = 容量 × 0.7 × 10
       稀缺(<30%容量) → 1.5~2.5倍
       泛滥(>150%容量) → 0.5~0.7倍
       正常 → 0.8~1.2倍
       跨域 → 再×1.2~1.8
    6. 根据场景生成狩猎故事文本
```

### 3.4 讨价还价流程 (`shop_bargain.gd`)

```
start_bargain(shop, adv):
    _is_bargaining = true
    根据性格定最大轮数:
        急躁:2, 普通:4, 耐心:6, 狡猾:3, 豪爽:3
    初始要价 = 货物价值 × 1.0~1.3
    显示弹窗
    set_modal_open(true)  # 锁定主界面

handle_submit(shop, adv):
    出价逻辑树:
    ├─ >= 要价 → 直接成交
    ├─ < 价值30% → 愤怒离开
    ├─ 急躁 + <要价70% → 直接走
    └─ 否则 → 概率判定:
        基础接受 = 15% + 已过轮数×12%
        + 性格修正 (耐心+20%, 狡猾-10%, 豪爽+15%)
        + 出价合理性 (>=价值80% → +40%)
        → clamped (0~95%)
        成功 → 成交
        失败 → 到最大轮数? → 谈判破裂
               → 没到 → 对方降价40%，继续

cancel_bargain(shop, reason_leave):
    _is_bargaining = false
    hide弹窗
    set_modal_open(false)
    如果 reason_leave == true → 生成下一位冒险者
```

### 3.5 怪物袭击流程 (`shop_monster.gd`)

```
check_monster_attack(shop):
    触发概率: 15% + day * 0.1%
    精英判定: 20% + day * 0.2%
    生成怪物名
    更新弹窗UI
    连接按钮信号:
        OptionBtn1 → _on_guard_clicked.bind(shop)
        OptionBtn2 → _on_fight_clicked.bind(shop)
    set_modal_open(true)

_on_guard_clicked(shop):
    费用 = 30 + day * 2
    金币不足时自动改为硬扛

_on_fight_clicked(shop):
    调用 _execute_fight_result(shop, false, ...)

_execute_fight_result(shop, had_guard, is_elite, monster):
    成功率: 守卫→70%, 硬扛→max(30%, 70%-day*1%)
    成功 → 掉落判定 (精英60%/普通30%)
           掉落物: 随机物种"残骸", 价值(10~50+精英30)
           掉落到inventory
    失败 → 随机丢失一件货架商品
    set_modal_open(false)  # 解锁
```

### 3.6 顾客购买流程 (`shop_customer.gd`)

```
process_customers(shop):
    顾客数量 = max(1, 1 + int(柜台等级 × 0.5) + rand(0~2))
    每个顾客:
        1. 随机偏好一种材料类型
        2. 从货架筛选同类型商品
        3. 无匹配 → 记录"缺货"
        4. 计算购买概率 buy_chance:
           buy_chance = clamp(0.9 - (售价/成本-1.0) × 0.5, 0.1, 1.0)
           × (0.8 + 信誉 × 0.004) + 柜台等级 × 0.02
           如果类型在生态中稀缺 → +20%, 且价格提升10~40%
        5. 成交 → 金币增加, 货架移除, 销售记录
           信誉变化 = (评分 - 3.0) × 2.0
        6. 评分规则:
           售价/成本 ≤ 1.0 → ★★★★★
           ≤ 1.3 → ★★★★
           ≤ 1.6 → ★★★
           ≤ 2.0 → ★★
           > 2.0 → ★
```

### 3.8 生态面板 (`shop_ecosystem_panel.gd`)

- **实现方式**: CanvasLayer覆盖层（非Window），层级 = 128
- **组件**: 全屏遮罩 → 固定位置Panel → ScrollContainer → VBoxContainer

## 5. 已知 Bug & 待解决问题

### 🐛 BUG-01: 生态面板滚动容器父节点错误（高优先级）

**问题描述**: 在 `shop_ecosystem_panel.gd` 的 `_create_panel()` 中，`ScrollContainer` 和 `_panel_container(VBoxContainer)` 被当作了 `screen`（全屏Control）的子节点，而不是 `panel`（生态面板Panel）的子节点。

**当前代码（错误）**:
```gdscript
# 第97~107行
var scroll = ScrollContainer.new()
scroll.position = Vector2(15, 60)
scroll.size = Vector2(570, 620)
screen.add_child(scroll)  # ← 错误！应该加到 panel 下

_panel_container = VBoxContainer.new()
scroll.add_child(_panel_container)  # 这个正确，scroll的容器没问题
```

**影响**: 生态面板的滚动区域和内容不会显示在面板内，而是出现在屏幕左上角。

**修复方案**: 将 `screen.add_child(scroll)` 改为 `panel.add_child(scroll)`。

---

### 🐛 BUG-02: 怪物袭击窗口按钮信号双重绑定

**问题描述**: `shop_monster.gd` 的 `check_monster_attack()` 每次调用都会重新 `connect` 按钮信号。虽然代码中有 `_safe_disconnect` 尝试断开旧连接，但在某些场景下（如守卫金币不足时递归调用 `_execute_fight_result` 再 `_on_guard_clicked`），可能导致按钮信号重复绑定。

**影响**: 极端情况下按钮点击可能触发两次回调。

**修复方案**: 在 `_safe_disconnect` 中使用完整Callable比较，或改用 `pressed.is_connected()` 检查。

---

### 🐛 BUG-03: 冒险者收购后生态物种减少目标域错误

**问题描述**: `shop_bargain.gd` 的 `_finalize()` 中有从冒险者来源域减少物种的代码。但 `ShopManager.gd` 的 `_on_btn_acquire()` 中硬编码了只从 `glowing_tundra` 减少物种，没有考虑到跨域商人场景。

**当前代码**:
```gdscript
# ShopManager.gd 第488行
_reduce_ecosystem(goods.get("name", ""))
# 该方法只查 glowing_tundra 域
func _reduce_ecosystem(item_name: String) -> void:
    var tundra = _sim.domains["glowing_tundra"]
    # ...
```

**影响**: 如果跨域商人卖非荧光苔原域的货物，收购后不会减少对应域的物种。

**修复方案**: 统一为从 `_current_adv.goods.domain` 获取来源域ID，确保正确减少对应域的物种。

---

### 🐛 BUG-04: 多个按钮场景中 text="" 无文字

**问题描述**: 场景中以下按钮的 `text` 为空字符串：
- `Btn_Acquire`（收购）
- `Btn_Bargain`（讨价）
- `Btn_Refuse`（拒绝）
- `Btn_PutOnSale`（上架）
- `Btn_BusinessLog`（经营日志）
- `Btn_SalesRecord`（销售记录）
- `Btn_EcologyPanel`（生态面板）
- `Btn_EndDay`（结束一天）

**ShopManager.gd 中没有对这些按钮设置文字的代码**，玩家运行时会看到空白按钮。

**修复方案**: 在 `_ready()` 中添加设置按钮文字的代码，或在场景文件中直接设置 text 属性。

---

### 🐛 BUG-05: `_bind_popup_signals()` 未连接怪物窗口按钮

**问题描述**: `ShopManager.gd` 第217-229行的 `_bind_popup_signals()` 中，讨价还价窗口的确认/取消按钮被正确连接，但怪物窗口的 OptionBtn1/OptionBtn2 被注释掉了：

```gdscript
# 怪物袭击窗口 - 由 shop_monster.gd 自己在 check_monster_attack() 中管理
# 此处不做连接，避免双重信号触发
```

**当前状态**: 怪物窗口按钮由 `shop_monster.gd` 的 `check_monster_attack()` 动态连接。这实际上是**有意为之的设计**（每次袭击重新绑定），不算bug，但需要注意 `_safe_disconnect` 的健壮性。

---

### 🐛 BUG-06: 库存上架后未刷新货架管理弹窗（部分场景）

**问题描述**: `_on_btn_put_on_sale()` 中有通知 `_shelf_manager.refresh()` 的逻辑，但 `_shelf_manager` 在 `_ready()` 中可能为 null 时的处理不够健壮。如果在 `_shelf_manager` 创建完成前调用上架，弹窗不会收到刷新通知。

**影响**: 极低概率的竞态条件。在场景启动早期上架时可能弹窗不更新。
